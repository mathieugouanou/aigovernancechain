# Project governance

How decisions are made in this repository. The binding rules are in [CHARTER.md](CHARTER.md); this page is the short version.

- **Day to day:** maintainers review and merge pull requests. Every change to `atlas/regimes/` needs a cited source and one maintainer approval; changes to a reviewed regime also need its named reviewer.
- **Current practice (10 Nov 2026):** the project has one maintainer, so no change has had a second reviewer yet, and most changes were committed directly. From 20 Nov 2026 every change arrives by pull request. Details in [AI_GOVERNANCE.md](AI_GOVERNANCE.md#human-oversight).
- **Releases:** v0.x releases are cut by the project lead. From v1 (30 Nov 2026) releases are approved by the Technical Steering Committee. Weekly Atlas releases start with v1.
- **Disagreements:** discuss in the issue; if unresolved after 7 days, a maintainer may escalate to the TSC, which decides under the charter.
- **Specification changes:** open an issue labelled `spec`. Breaking changes need a new spec id and a 14-day comment period.
- **Security and conduct:** see [SECURITY.md](SECURITY.md) and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
